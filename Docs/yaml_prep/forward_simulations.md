# Forward (experiment) simulation inputs

---

Currently, FANTASTX supports 5 different experimental methods. These are:

- Transmission electron microscopy (TEM)

- Scanning transmission microscopy (STM)

- X-ray absorption spectroscopy (XAS)

- Pair distribution function (PDF) analysis

- X-ray diffraction (XRD)

Each one of these experimental methods requires different inputs to the [FANTASTX input yaml file](index.md), and different external files that need to be included in the FANTASTX job folder. Each one will be covered in turn.

## Transmission Electron Microscopy (TEM)

FANTASTX runs TEM simulations via integration with the [Ingrained](https://github.com/MaterialEyes/Ingrained) package. As such, FANTASTX only requires a path to the reference experimental image that is being inverted, and a set of Ingrained optimization parameters. These Ingrained optimization parameters can either be provided in the form of an Ingrained progress file, helpful if Ingrained is used to perform initial optimization, or a list of parameters in the order that Ingrained expects.

### Experimental Image

The experimental TEM image can be provided as a DM3 or a raw image data file. If provided as a DM3, then a path to the DM3 should be provided. If provided as a raw image data file (i.e. as a matrix), then FANTASTX expects it to be located in the subfolder `inputs` within the FANTASTX job directory, and named 'whole_exp.npy'. 

### Optimization Parameters

The optimization parameters can be provided in the form of an **Ingrained progress file**, or as a **list**. Regardless of how the optimization parameters are provided, it should be noted that FANTASTX only utilizes the first three Ingrained optimization parameters. These are:

1. The pixel size

2. The interface width (set to zero when matching an entire image)

3. The defocus

### FANTASTX YAML inputs

The TEM FANTASTX label is 'GB_STEM'. The input to the FANTASTX YAML file, including all optional inputs, would be:

!!! example
    ```YAML
    exp_sim_1: 'GB_STEM'
    exp_sim_1_params: # GB STEM simulation parameters
        dm3_path: # path to raw TEM .dm3 file, exclude if data provided as a numpy matrix at inputs/whole_exp.npy
        progress_file: # path to progress_file from Ingrained optimization (optional if ing_opt_params provided instead)
        ing_opt_params: [0.26, 0, 1.66938749] # pixel size, interface width, defocus (optional if progress file provided instead)
    ```

## X-ray Absorption Spectroscopy (XAS)

FANTASTX runs XAS simulations by interfacing with third party codes. Currently, supported codes are FEFF and FDMNES. All XAS simulations are run, post-processed, optimized and quantified via the [Xanes ToolKit (xtk)](https://github.com/MaterialEyes/xtk) package. The inputs to FANTASTX are more extensive than for most of the other forward simulations. 

### Experimental and Computational Reference Spectra

FANTASTX can interface with either XANES spectra or difference spectra, as would be encountered in XTA.

If the target of inversion is a XANES spectra, then only the experimental XANES spectra is required. FANTASTX expects the format of the spectra to be a text file, with a column labeled 'Energy' and a column labeled 'Mu'.

If the target of inversion is a difference spectra, such as encountered in XTA, then both the experimental difference spectra and a computational reference spectra are required. Just like with XANES spectra, the experimental difference spectra should be provided as a text file with columns labeled 'Energy' and 'Mu'. It can also be provided as an two-item iterable, where FANTASTX reads in both files and takes the difference as the absorbance ('Mu') of file two minus the absorbance of file one. 

Additionally, if the target of inversion is a difference spectra, then a reference computational spectra must also be provided. This spectra will be the base, and the difference spectra generated by FANTASTX will be the newly simulated spectra minus the base spectra. Just like with the experimental spectra, FANTASTX expects this spectra to be a text file with columns labeled 'Energy' and 'Mu'.

The experimental file(s) should be provided with the `experimental_filepath` keyword, with either a string or as a list of two strings as the value. The computatational base file should be provided with the `comp_base_filepath` keyword with a string as the value. 

### Input File for the Simulation Code

FANTASTX runs the simulation code by providing a YAML file with all of the variable inputs. The format of the input file is the same regardless of whether FEFF or FDMNES is used, however the keys that are provided are of course different depending on which code is used. For a guide on preparing this input YAML file for the XAS simulation codes, refer to [this](../xanes.md) section. The path to this file should be provided to FANTASTX in the FANTASTX YAML with the `input_yaml_filepath` keyword. 

### Simulation Code

As mentioned above, FANTASTX is currently capable of interfacing with the forward XAS simulation codes FEFF and FDMNES. The user needs to tell FANTASTX which code to use, where FANTASTX can find that code, and provide commands to run the chosen code using MPI. 

In particular, the user needs to provide FANTASTX with the following information:

- Simulation code (`simulation_code`): 'FEFF' or 'FDMNES'

- Execution command (`exec_cmd`): how to execute the chosen code. Full MPI command for FDMNES, executable command for FEFF. See YAML examples below.

- Code folder (`code_folder`): the folder where the simulation code can be found.

- MPI command (`mpi_cmd`): (FEFF only) the MPI command (excluding the executable) used to run the code.

### XTK Inputs

The inputs for XTK can be divided into the following categories: quantifying spectral distance, fitting data with a spline, convolution, and optimization (with respect to the experimental spectra).

#### Distance Quantification

This is provided to the FANTASTX YAML as `spectra_distance_metric`. The possible options are: 'euclidean', 'wasserstein', 'cosine', 'laplacian', 'chi2', 'cityblock', 'canberra', or 'correlation'. All of these metrics are computed by Scikit-learn or SciPy. To learn more, visit Scikit-learn's page on [pairwise distances](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.pairwise_distances.html), or SciPy's page on [spatial distances](https://docs.scipy.org/doc/scipy/reference/spatial.distance.html).

#### Spline Mesh

FANTASTX fits both the experimental and simulated spectra with a cubic spline in order to allow spectra comparison at the same energy values, regardless of the discretization of either spectra. This spline is fit across a uniform mesh, and the user must provide the start, end, and step values for the mesh. These must be provided in the form of a list, as [start, stop, step].

#### Convolution

After the simulated spectra is fit with a spline, it can be convolved with a user chosen function in order to broaden and shape the spectra, making the simulated spectra more realistic to experimental spectra. This convolution can be performed with a function of constant width, or a function whose width changes with energy. In the majority of cases, using a constant width is the most physically realistic. However, if adding a variable broadening term, the width dependence can be linear, corresponding to broadening linearly increasing with higher energy, or correspond to an arctangent function. The latter is actually **required** for FDMNES, which uses this arctangent convolution to account for a variety of experimental spectral features. 

!!! information "Broadening Functions"
    === "Linear Broadening Function"

        The function of the linear broadening $\Gamma(\textrm{E})$ is:

        $\Gamma(\textrm{E}) = \Gamma_\textrm{ch} + \frac{\textrm{E} - \textrm{E}_0}{\textrm{E}_\textrm{max} - \textrm{E}_0} * (\Gamma_\textrm{max} - \Gamma_\textrm{ch})$

        In this function, $\textrm{E}_\textrm{max}$ and $\textrm{E}_0$ are assumed to be the upper and lower limits of the energy range over which the convolution is applied. See below for a description of the $\Gamma$ terms.
    
    === "Arctan Broadening Function"

        The function of the arctan broadening $\Gamma(\textrm{E})$ is given by:

        $\epsilon = \frac{\textrm{E} - \textrm{E}_\textrm{fermi}}{E_\textrm{cent}}$

        $\alpha = \epsilon - \frac{1}{\epsilon^2}$

        $\beta = \arctan( \frac{\pi}{3} * \Gamma_{max}/\textrm{E}_\textrm{larg} * \alpha)$

        $\Gamma(\textrm{E})= \Gamma_\textrm{ch} + \Gamma_\textrm{max} * ( 1/2 + \frac{\beta}{\pi})$

        See below for a description of each of the variables. 

The user can choose the following settings:

- Kernel (`kernel`): 'gaussian' or 'lorentzian'

- Energy dependence (`x_dependence`): 'none', 'linear' or 'arctan'

- Arguments (`arguments`):

    - $\Gamma_\textrm{ch}$ (`g_ch`): the core-hole width in eV

    - $\Gamma_\textrm{max}$ (`g_max`): the maximum core-hole width in eV. If linear energy dependence, the core hole width will linearly increase from g_ch to g_max. Also the maximum core-hole width for arctan energy dependence.

    - $\textrm{E}_\textrm{cent}$ (`e_cent`): (arctan specific) the center of the arctangent function in eV, relative to the Fermi level

    - $\textrm{E}_\textrm{larg}$ (`e_larg`): (arctan specific) the width of the arctangent function in eV

    - $\textrm{E}_\textrm{fermi}$ (`fermi_energy`): (arctan specific) the fermi energy relative to the edge position measured by FDMNES. 

- Fermi energy extraction (`extract_fermi_energy`): (FDMNES only) boolean, used to determine if the Fermi energy should automatically be extracted from the simulation results.

#### Optimization

Once the spectra has been fit with a spline, it is possible to have FANTASTX optimize various parameters in order to achieve the minimum possible distance between the simulated spectra and the experimental spectra. To do so, FANTASTX utilizes either local or global optimization, both as implemented in SciPy. All of their global optimizers as well as local optimization via the `minimize` function are implemented for use, namely: 'differential_evolution', 'basinhopping', 'shgo', 'brute', 'dual_annealing', 'direct', and 'minimize'. Each of these methods has specific optimization options that can also be provided. For information on each optimization method and the options available for each one, see the [SciPy optimization page](https://docs.scipy.org/doc/scipy/reference/optimize.html). 

This optimization will tune any variables which are used in the convolution, as well as the shift (in energy) and scale (of absorption) of the spectra. If analyzing a difference spectra, the simulated spectra itself can be shifted and scaled, as well as shifting and scaling the resulting difference spectra (in essence shifting and scaling the two simulated spectra by the same amounts).

In addition to providing a starting guess for each value (apart from the shift and scale), the user must provide bounds for each variable. In sum, the user can choose the following settings:

- Optimization metric (`metric`): same set of options as `spectra_distance_metric` [above](#distance-quantification)
- Optimization options (`opt_options`): [optimizer specific options](https://docs.scipy.org/doc/scipy/reference/optimize.html), provided as YAML entries. 
- Optimization method (`opt_method`): chosen optimization method
- Optimizer bounds (`opt_bounds`): set of YAML entries, one for each convolution variable, and shift and scale variables. Bounds should be provided as a two-member iterable. Entries should be provided matching the [convolution variable entries](#convolution), plus a `shift` and a `scale` entry. 
    - If inverting a difference spectra, then the 'shift' and 'scale' parameters should be provided as `shift_diff` and `scale_diff`. In addition, if the user wants to independently shift and scale the simulated spectra itself, then providing optimization bounds for `shift_targ` and `scale_targ` will enable (and perform) this independent optimization. 
- Optimization window (`opt_window`): the energy window within which the match between the simulated and experimental spectra will be optimized. Should be provided as a two-member iterable.

## Pair Distribution Function (PDF)

FANTASTX runs PDF simulations by interfacing with [Diffpy](https://www.diffpy.org/), a third party code. In addition to the experimental PDF file, the user must also provide various PDF variables, as well as bounds for fitting these variables. Additionally, the user can also allow Diffpy to optimally adjust the atomic coordinates in order to improve the match between the simulated PDF and the experimental PDF. This is generally not recommended, but can give better results in some cases.

### Experimental PDF

The experimental PDF file is provided in the `exp_sim_params` section of the FANTASTX YAML file with the keyword `exp_pdf_file`. This file should be a headerless text file, with the first column giving the x value (the real space distribution in units of Å), and the second column giving the pair distribution function itself.

### Tuning the PDF Simulation

A variety of PDF variables can be set in order to tune the performance of the PDF simulation. These can be split into three categories: 1) PDF simulation variables, 2) PDF range variables, and 3) unit cell variables. FANTASTX will provide default values, but it is best to know what each does and be able to set the bounds appropriately.

Additionally, the user has control over which optimization method is employed by Diffpy to adjust these variables, tuned by setting the `minimize_method` keyword in the `exp_sim_params` section of the FANTASTX YAML file. The options are 'L-BFGS-B', corresponding to the limited-memory Broyden-Fletcher-Goldfarb-Shanno algorithm extended to handle simple bound constraints, and 'SLSQP', corresponding to the Sequential Least Squares Programming algorithm. In the backend, Diffpy utilizes the [SciPy implementations](https://docs.scipy.org/doc/scipy/reference/optimize.html) for both of these algorithms. 

#### PDF Simulation Variables

FANTASTX employs the following set of Diffpy variables: 'Biso', 'delta2', 'scale', and 'qdamp'.  

The variable 'Biso' is the crystallographic Deby-Waller [B-factor](https://www3.cmbi.umcn.nl/bdb/theory/) (also known as the isotropic B-factor or the atom-pair disorder factor), which is related to the isotropic thermal displacement factor **U** via: $\textrm{B}_\textrm{iso} = 8 * \pi^2 * \textrm{U}$. The default FANTASTX optimization range for Biso is 7.896e-4 to 2.00096, and the default FANTASTX value is 0.71.

The variable 'delta2' is the coefficient for $1/\textrm{r}^2$ contributions to peak sharpening. This describes the low temperature behavior, while 'delta' controls the high temperature behavior. The two parameters are highly correlated, so FANTASTX only uses 'delta2' for refinement. The default FANTASTX optimization range for 'delta2' is 2.0 to 5.0, and the default FANTASTX value is 3.87.

The variable 'scale' controls the scaling of the PDF. The default FANTASTX optimization range for 'scale' is 0.5 to 1.5, and the default FANTASTX value is 1.0.

The variable 'qdamp' is a peak-damping resolution term, controlling the PDF Gaussian dampening envelope due to limited Q-resolution. The Gaussian envelope is of the form: $B(r) = e^{-\frac{(r*Q_{damp})^2}{2}}$. The default FANTASTX optimization range for 'qdamp' is 0.001 to 0.1, and the default FANTASTX value is 0.043.  

The initial guesses for the values of each of these variables should be set in the `exp_sim_params` section of the FANTASTX YAML using keywords with the same names. For instance, the qdamp value is set by using the `qdamp` keyword. The exception is 'Biso', which should be set with `Biso_val`. If the keyword for any of the variables is not provided, then the matching default value will be used instead.

The bounds for each variable should be set by adding a two item list as the value of the corresponding sub-keyword to the `var_bounds` keyword in the `exp_sim_params` section of the FANTASTX YAML file. For instance, if setting bounds for 'Biso' of 0.01 to 2.1, then the keyword `Biso_val` would be added to `var_bounds`, with the value [0.01, 2.1]

#### PDF Range Variables

Variables can be added to tune the reciprocal space range over which Diffpy calculates the PDF, and the real space range over which comparison is made (and the results are plotted). The reciprocal space range is controlled via the `Qmin` and `Qmax` variables, while the real space range is controlled by the `xmin`, `xmax`, and `dx` variables.

The default FANTASTX values for `Qmin` and `Qmax` are 0.0 and 50.0 respectively. The default FANTASTX values for `xmin`, `xmax` and `dx` are 0.5, 10.0 and 0.1 respectively. `dx` is the resolution of the real space grid. Adding the identical keyword to the `exp_sim_params` section of the FANTASTX YAML file will adjust the corresponding default value for each of these. These variables are not optimizable.

#### Unit Cell Variables

Diffpy can also adjust the unit cell in order to tweak the simulated PDF. FANTASTX has implemented support for this unit cell adjustment. Currently, the FANTASTX treatment is such that if the lattice is cubic, then it is kept cubic, only adjusting the 'a' lattice parameter and scaling the 'b' and 'c' lattice parameters accordingly to maintain cubic symmetry. In this case, the lattice angles $\alpha$, $\beta$ and $\gamma$ are kept as $\pi/2$. However, if the lattice is not cubic, then the 'a', 'b' and 'c' lattice parameters are independently adjusted, with the lattice angles kept at the same initial values.

Bounds can be set for the adjustments of the lattice parameters. These should be included under the `var_bounds` keyword in the `exp_sim_params` section of the FANTASTX YAML file, just like the PDF simulation variables [above](#pdf-simulation-variables). Each bound can be provided as a single float, or as a two item iterable. For example, if a single float $\alpha$ is provided as the bound for the **a** lattice parameter, then the bounds of **a** will be set as:

$\textrm{a}_\textrm{lower bound} = \textrm{a}_\textrm{initial} - \alpha * \textrm{a}_\textrm{initial}$

$\textrm{a}_\textrm{upper bound} = \textrm{a}_\textrm{initial} + \alpha * \textrm{a}_\textrm{initial}$

In contrast, if a two item iterable is provided, corresponding to [lower bound, upper bound].

The default bounds for each lattice parameter are a float bound of 0.02 (allowing for an adjustment of the lattice parameter of up to 2%).

### Coordinate Adjustment

Diffpy is also capable of adjusting the atomic coordinates! It uses the same optimizer for this adjustment as it uses for tuning the PDF simulation. This optimization can be turned on by including the `fit_coords` keyword in the `exp_sim_params` section of the FANTASTX YAML file, and setting the value to be `True`. The amount that the coordinates are allowed to be adjusted in units of Å is given by the `coord_tol` keyword in the `exp_sim_params` section of the FANTASTX YAML file. The default value for this 'coodinate tolerance factor' is 0.1.

## X-ray Diffraction (XRD)

FANTASTX runs XRD simulations by interfacing with [GSASII](https://subversion.xray.aps.anl.gov/trac/pyGSAS), a third party code. In addition to the experimental XRD file and assorted simulation parameters, the user must also provide instrument parameters from an initial GSASII XRD fit.

### Experimental XRD

The experimental XRD file is expected to be in the format of a headerless text file, with the first column corresponding to $2\theta$ and the second column corresponding to the measured diffraction data.

The path to the file should be provided via the `exp_xrd_file` keyword in the `exp_sim_params` section of the FANTASTX YAML file.

### GSASII Instrument Parameters File

A key component of successfully running XRD simulations in FANTASTX is providing a reliable instrument parameter file in FANTASTX. The easiest way to do this is using the GSASII GUI, fitting to the experimental XRD data. This will yield a set of instrument parameters capable of successfully matching the XRD pattern of an atomic configuration to the experimental data.

For a guide on preparing the instrument parameter file, which will have a .instprm extension, follow [the GSASII tutorial](https://subversion.xray.aps.anl.gov/pyGSAS/Tutorials/CWInstDemo/FindProfParamCW.htm). Once you have obtained reasonable instrument parameters, save the file. Then, provide the filepath to FANTASTX via the `instr_param_file` keyword in the `exp_sim_params` section of the FANTASTX YAML file.

??? example "Example GSASII .instprm file"
    ```txt
    #GSAS-II instrument parameter file; do not add/delete items!
    Type:PXC
    Bank:1.0
    Lam1:1.5405
    Lam2:1.5443
    Zero:0.0
    Polariz.:0.7
    Azimuth:0.0
    I(L2)/I(L1):0.5
    U:-1048.3358391365862
    V:462.80968790097387
    W:160.72614697393863
    X:9.305150948850233
    Y:47.55030794993898
    Z:0.0
    SH/L:0.002
    Source:?
    ```

### Additional XRD Parameters

FANTASTX also requires the user to provide parameters governing the range and discretization over $2\theta$ for both the simulation and quantifying the mismatch between the simulation and experiment.

The simulation range is governed by the input keywords `xmin`, `xmax` and `npoints` in the `exp_sim_params` section of the FANTASTX YAML file. Default values for FANTASTX are 15.0, 65.0, and 1250.

The fitting range (over which the simulation-experiment mismatch is quantified) is governed by the input keywords `xmin_fit`, `xmax_fit` and `npoints_fit` in the `exp_sim_params` section of the FANTASTX YAML file. Default values for FANTASTX are 20.0, 60.0, and 2001. 

FANTASTX also allows the user to select the metric used to quantify the mismatch between the simulated and experimental XRD. The distance metric choices, provided in the the `exp_sim_params` section of the FANTASTX YAML file with the keyword `score_method`, are: 'res_sim', 'res_fit', 'emd_sim' and 'emd_fit'. 'res_sim' and 'res_fit' correspond to the residual, here taken to be the mean absolute error scaled by the 'y' range of the experimental data, measured between the raw simulated PDF and the experimental PDF ('res_sim') or between the fitted simulated XRD and the experimental XRD ('res_fit'). 'emd_sim' and 'emd_fit' correspond to the [earth mover's distance](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.wasserstein_distance.html), again measured between the raw simulated PDF and the experimental XRD ('emd_sim') or between the fitted simulated PDF and the experimental XRD ('emd_fit'). The default FANTASTX metric is 'res_fit'.

Finally, the user can also select the scaling factor for the XRD histogram. This value should be provided via the `scale` keyword in the `exp_sim_params` section of the FANTASTX YAML file. The default FANTASTX value is 100.

### FANTASTX YAML Inputs

The XRD FANTASTX label is 'XRD'. A full input to the FANTASTX YAML file would be:

!!! example
